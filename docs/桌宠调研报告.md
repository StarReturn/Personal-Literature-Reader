## 二、逐项分析

### 2.1 BongoCat —— 工程标杆（同技术栈，重点参考）

- **地址**：<https://github.com/ayangweb/bongocat>（官网 <https://bongocat.pet/>）
- **是什么**：Tauri 构建的跨平台桌宠，一只 Live2D 猫常驻桌面；主播直播时展示实时键盘敲击动画而爆火（B 站直播间的"自证清白猫"）。
- **核心功能**：
  1. 键鼠实时联动——敲键盘猫跟着敲、鼠标移动猫爪跟随、眼睛追踪鼠标位置
  2. 透明置顶窗口，与桌面无缝集成、不遮挡操作
  3. **按屏幕分辨率加载不同清晰度模型**，保证 60 帧流畅（不同硬件实测均丝滑）
  4. 跨平台（Windows/macOS/Linux）+ 游戏手柄输入支持
- **对本项目的借鉴**（同是 Tauri，可直接读源码抄实现）：
  - 透明窗口 + 无边框置顶的工程细节
  - **透明区域点击穿透**（v1 遗留项）的成熟做法
  - 全局键鼠监听（Rust rdev → 前端事件）
  - 多分辨率素材分级加载策略

### 2.2 VPet —— 功能与生态标杆（形象包格式参考）

- **地址**：<https://github.com/LorisYounger/VPet>（Steam 版有创意工坊）
- **是什么**：WPF/C# 开源桌宠，源自虚拟主播模拟器的内置桌宠，功能天花板级：投喂、摸头等丰富互动、大量动画、状态系统（饥饿/心情等）。
- **核心机制**：
  1. **MOD 模组系统**：自定义角色、动画、互动均可打包成模组；官方提供 MOD 制作器
  2. Steam 创意工坊分发，玩家上传/订阅桌宠角色
  3. 核心库（VPet-Simulator.Core 等）发布 NuGet，可嵌入任意 WPF 应用
- **对本项目的借鉴**：
  - **形象包格式学它的 mod 结构**：一个角色 = 一个文件夹（立绘 + 各动作帧 + 配置），恰好匹配我们"动作我们预设、形象开放生成"的定位——v2 可把"动作槽"升级为**形象包 zip**（`立绘.png / 打盹.png / 挥手.png / 台词.json`）
  - 状态系统思路（心情/喂食）远期可选，非重点

### 2.3 Live2DMascot —— Live2D 路线代表（暂缓印证）

- **地址**：<https://github.com/Arkueid/Live2DMascot>
- Live2D 模型直接上桌面、自由拖拽。代表"真·骨骼动画"重路线：模型制作/授权成本高、集成复杂（pixi-live2d-display 等 web 方案成熟但体积大）。
- **结论印证**：我们 v1 选择"PNG + 刚体动画"、Live2D 暂缓的判断与业界轻量做法一致；若未来升级，先评估模型获取成本再立项。

### 2.4 Pet-GPT —— AI 联动思路（差异化启发）

- **地址**：<https://github.com/Hanzoe/Pet-GPT>
- PyQt 桌宠接入 OpenAI，能上下文对话、**主动搭话**。
- **启发**：桌宠 + AI 播报的组合可行。我们独有优势是应用内状态——不必做闲聊，让猫做"**文献工作播报员**"（阅读周报、备份提醒、导入完成通知），与外部 AI 工作流呼应。

### 2.5 dsh-pet —— 状态反射型（同思路验证）

- Electron 小鲸鱼桌宠：实时反映会话状态（工作中/待确认/任务完成/空闲），素材零代码自定义。
- 验证了"**应用状态 → 桌宠表现**"这条差异化路线成立，与 v1 已实现的"导入完成冒泡"方向一致。

## 四、对本项目 v2 的落地建议

1. **工程细节抄 BongoCat**：透明窗穿透、性能、（可选）键鼠监听——同栈直接读源码，少踩坑。
2. **形象包格式抄 VPet**：动作槽升级为形象包 zip（立绘 + 动作帧 + 台词配置），用户用 GPT 生成一套图即可完整换装；配合形象管理界面。
3. **差异化打"文献伴侣"**：阅读进度/备份提醒/笔记周报播报——调研中无一家做应用状态联动，这是我们与纯陪伴型桌宠的区隔。
4. **Live2D 暂缓**：模型成本与体积不匹配个人工具定位，帧动画 + 刚体引擎已覆盖核心体验。
5. **v2 排期建议**（按优先级）：
   - P0：透明区点击穿透（BongoCat 方案）、形象包 zip 导入 + 动作槽帧动画
   - P1：应用事件播报（导入完成/备份提醒/今日阅读小结台词）
   - P2：键鼠趣味联动（眼睛跟鼠标）、多分辨率素材分级
